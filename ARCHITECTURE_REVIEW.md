# Architecture Review
Generated: 2026-09-02T20:24:44.333Z
Score: 76/100

## Summary
This is a small, well-structured React mini-app (Toss Apps-in-Toss chore-splitting app) with a clear layering: types → lib (pure logic) → store (state) → components (presentational) → pages. State management and error-handling patterns (guarded SDK calls) are applied consistently. The main weaknesses are repeated boilerplate across page components (haptic wrappers, tab configs, Chip casting, toast state) that should be extracted into shared modules, plus a duplicated/divergent 'today' date helper and a few unused exports.

## Issues
### Warnings
- [duplication] Nearly identical `todayKST()` logic exists in two places with two different implementations: storage.ts exports a canonical `todayKST`, but streak.ts independently redefines a private, non-exported `todayKST()` using a different calculation method (UTC+9 ms offset) instead of importing the shared one. If the two implementations ever diverge (e.g. edge-case rounding), streak/ranking calculations would silently disagree with the rest of the app's notion of 'today'. — Files: src/lib/storage.ts, src/lib/streak.ts / Fix: Delete the local todayKST in streak.ts and import the exported todayKST from storage.ts (or move the KST-date helper into a single shared date-utils module that both import).
- [duplication] `safeHaptic`/`fireHaptic` — an identical try/catch wrapper around `generateHapticFeedback` — is copy-pasted in at least 7 different files (Members, Chores, ReportDetail, Settings, Settle, Report, Streak) plus a near-duplicate `fireHaptic` in BottomCTA.tsx and inline haptic logic in FloatingTabBar.tsx. — Files: src/pages/Members.tsx, src/pages/Chores.tsx, src/pages/ReportDetail.tsx, src/pages/Settings.tsx, src/pages/Settle.tsx, src/pages/Report.tsx, src/pages/Streak.tsx, src/components/BottomCTA.tsx, src/components/FloatingTabBar.tsx / Fix: Extract a single `safeHaptic(type)` utility into src/lib/haptics.ts and import it everywhere instead of redefining it per file.
- [duplication] The `TAB_ITEMS` array (홈/리포트/스트릭/설정 tab config) is copy-pasted verbatim in four page files instead of being defined once. — Files: src/pages/Home.tsx, src/pages/Report.tsx, src/pages/Settings.tsx, src/pages/Streak.tsx / Fix: Move TAB_ITEMS into a shared constant (e.g. src/lib/navigation.ts or a const alongside FloatingTabBar) and import it in all four pages.

### Suggestions
- [duplication] The same `Chip = TdsChip as unknown as ComponentType<ChipButtonProps>` re-cast (with a near-duplicate local `ChipButtonProps` type, inconsistent between files — Chores.tsx omits `variant` while Home/Report/Streak include it) is repeated in four page files, each with its own comment explaining the same workaround. — Files: src/pages/Chores.tsx, src/pages/Home.tsx, src/pages/Report.tsx, src/pages/Streak.tsx / Fix: Create one shared `Chip` wrapper component/type (e.g. src/components/Chip.tsx) with the full ChipButtonProps and import it everywhere instead of re-casting per page.
- [duplication] `weightLabel`/`freqLabel` helper functions are duplicated identically between Chores.tsx and Home.tsx. — Files: src/pages/Chores.tsx, src/pages/Home.tsx / Fix: Move weightLabel/freqLabel into src/lib/utils.ts (or a chore-formatting module) and import from both pages.
- [consistency] Every page re-implements its own `toastOpen`/`toastText` useState pair plus a `<Toast .../>` render block with the same open/onClose wiring, rather than sharing a hook. — Files: src/pages/Chores.tsx, src/pages/Home.tsx, src/pages/Members.tsx, src/pages/Onboarding.tsx, src/pages/Report.tsx, src/pages/Settings.tsx, src/pages/Settle.tsx / Fix: Extract a `useToast()` hook (returns {open, text, show, onClose}) to remove repeated boilerplate across all pages.
- [consistency] Import path style is inconsistent: App.tsx/main.tsx use relative imports (`./pages/Home`, `./lib/store`) while most components/pages use the `@/` alias (`@/components/ScreenScaffold`). Within src/lib itself, store.tsx/household.ts import sibling files with relative paths (`./types`) while streak.ts imports the same sibling via the `@/lib/types` alias. — Files: src/App.tsx, src/main.tsx, src/lib/store.tsx, src/lib/streak.ts, src/lib/household.ts / Fix: Standardize on the `@/` alias (or relative paths) project-wide and enforce via an eslint import rule.
- [dead_code] `cn()` and `formatCurrency()` are exported from src/lib/utils.ts but no shown file imports or uses either — only `formatNumber` is consumed (by Amount.tsx, CountUp.tsx, ReportDetail.tsx, Settle.tsx). — Files: src/lib/utils.ts / Fix: Remove cn/formatCurrency if truly unused, or wire formatCurrency into Amount/CountUp if currency formatting was intended there.
- [dead_code] src/lib/contract.ts declares a set of function-signature types (loadStateFn, saveStateFn, createHouseholdFn, buildWeeklyReportFn, computeSettlementFn, getStreakFn, getRankingFn, useAppStateFn, SettingsPatch) that are documentation/spec artifacts for a generation process rather than types consumed by any implementation file shown — no file imports these Fn types. — Files: src/lib/contract.ts / Fix: If these are purely codegen/spec documentation (per the header comment), move them out of src/lib (e.g. into a /spec or /docs folder) so `lib/` only contains code actually consumed at runtime/compile time; otherwise wire the real implementations to satisfy these type contracts explicitly (e.g. `const loadState: loadStateFn = ...`).
- [structure] src/pages/__TdsGallery.tsx is a dev-only component gallery, not a real page, but lives in src/pages alongside actual routed pages, relying on a double-underscore naming convention plus DEV-only conditional import to signal its special status. — Files: src/pages/__TdsGallery.tsx, src/App.tsx / Fix: Move dev-only tooling pages to a separate folder (e.g. src/dev/TdsGallery.tsx) so src/pages only contains real routes, and import from there in the DEV-only lazy import.
- [consistency] The `if (!ready) return <ScreenScaffold>...<LoadingState .../></ScreenScaffold>` early-return pattern is duplicated per page with slightly different top titles/row counts, rather than being handled by a shared layout/guard. — Files: src/pages/Settings.tsx, src/pages/Settle.tsx, src/pages/Home.tsx, src/pages/Members.tsx, src/pages/Streak.tsx / Fix: Consider a small `useReadyGuard`/`RequireReady` wrapper or a prop on ScreenScaffold to centralize the loading-state boilerplate.
